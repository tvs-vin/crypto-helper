# Crypto bot: project guide for Claude Code

## What this is
A self-hosted web dashboard that will grow into a crypto trading bot. It runs on a headless VM and is used through a browser from another machine.

The owner is **new to crypto**. If something they ask for is impossible, unsafe, or unnecessary in crypto terms, say so plainly and propose the safer alternative **before** building it. Do not just comply. Explain crypto concepts in plain language when they come up (see the glossary in `docs/SPEC.md`).

All requirements, the permission model, the data model, the API and the build order are in **`docs/SPEC.md`**. Read it before starting. Work **one milestone at a time** and stop after each one to report what was built, how it was tested, and what you recommend next.

## Non-negotiable rules
1. **No real funds in phases 1 to 3.** Phase 1 uses paper balances and public price data only. No exchange credentials are stored in phase 1.
2. **Never create or accept an exchange API key with withdrawal permission.** Read-only first, trade-only later. If the owner pastes a key with withdrawal enabled, tell them to delete it and make a new one. *(Footnote, owner 2026-10-28: this holds for now and may be revisited later. If it ever is, withdraw-capable keys would need their own special permission (given on purpose, in no preset) and the safeguards in `WIKI/project/decisions.md` "Real transfers". Until the owner explicitly decides that, build nothing for it.)*
3. **Secrets never go in git, logs, or chat.** Passwords, API keys, session tokens, TOTP secrets and seed phrases are never logged, printed, or committed. Config comes from environment variables or a secrets file outside the repo. `.env` and `data/` are gitignored.
4. **Never ask the owner for a seed phrase or private key.** Never build a feature that stores one.
5. **Use vetted libraries for security.** argon2-cffi for password hashing, pyotp for TOTP, `secrets` for tokens, `hmac.compare_digest` for comparisons. Do not invent crypto or auth schemes.
6. **Server-side permission checks on every endpoint.** Hiding a button in the UI is not security. Every state-changing action writes an audit log entry.
7. **Money is `Decimal` (stored as string), never `float`.**
8. **Bind to `127.0.0.1` by default.** Remote access goes through an SSH tunnel, Tailscale, or Cloudflare Access, never a bare open port.
9. **Real-money transfers (phase 4):** the app never holds a key that can sign. It prepares the transaction and the owner approves it on a hardware wallet or via WalletConnect, after a small test transfer.
10. **No unattended live trading** until paper trading has run cleanly for at least 2 weeks, the kill switch has been tested, and max-loss limits are enforced in code.

## Stack (defaults, change only with the owner's OK)
- Python 3.12+, FastAPI, SQLAlchemy 2.x with SQLite, pytest
- Frontend: vanilla JavaScript ES modules, no build step, served by FastAPI from the same origin
- Strict Content-Security-Policy (no inline scripts); build DOM with `textContent` / element APIs, never `innerHTML` with data
- Ask before adding dependencies that touch money or networks (exchange SDKs, web3 libraries)

## Conventions
- Every endpoint gets tests, **including the permission-denied cases**.
- One commit per milestone minimum, with a clear message.
- Keep the permission catalog in one module so new features can add permissions in one place.
- When commands exist (run, test, lint), add them to the section below.
- **Schema changes ship as an Alembic migration** in `app/migrations/versions/` (numbered `0003`, `0004`, ...; see `WIKI/reference/database-migrations.md`). `test_migrations_build_exactly_the_models` fails if models and migrations disagree.
- **Secrets at rest are encrypted** with `app.crypto` (`request.app.state.secret_box`). Never store a credential in plain text.
- **Account operations** shared by the API and the CLI live in `app/accounts.py`; callers commit and audit. Wallet/holding/transfer rules live in `app/wallets.py` the same way.
- **Money:** parse with `app.money.parse_amount` (text only; JSON numbers are refused), do arithmetic with `money.add/subtract`, output with `money.format_amount`. Anything that checks a balance and then changes it calls `app.db.begin_immediate(db)` first (SQLite write lock), and runs in one transaction.
- **Free text that a user could paste a secret into** goes through `app.wallets.guard` / `app.secret_guard.find_secret` before it's stored. Never echo the rejected text; 422 handler in `app/main.py` strips `input` from validation errors.
- **Networks and coin-network table:** only in `app/networks.py` (mirrored in `WIKI/reference/networks.md`).
- **Prices:** always read through `request.app.state.prices.snapshot(db)` (one shared, cached snapshot; pass the request's session). Never call CoinGecko from a request directly. Parse provider numbers into `Decimal` (`json.loads(parse_float=Decimal)`); round fiat values with `app.prices.valuation.round_fiat`. Tests run with the mock provider and no background job (set in `tests/conftest.py`).
- **Web app** (`app/web/`, served by `app/routers/web.py`): vanilla ES modules, no build step, strict CSP. Build DOM only with `dom.js` `h()` (textContent); never `innerHTML`/`eval` (`tests/test_web.py` enforces it). Every color/size comes from a CSS variable set by a `.ctheme` (data-only, validated by `app/themes.py` and again by `js/theme.js`). Window geometry maths lives in pure `js/tiling.js` (tested by `node --test tests/js/*.test.mjs`). Layout saves are debounced; flush them (`saveNow`) before anything ends the session. Only one sign-in box at a time (`signIn` in `main.js`).
- **Windows** live in `app/web/js/panels/`. An app may have several windows (`max` in `panels.js` = `max_windows` in `app/apps.py`; ids `overview`, `overview:2`…), so a window must never use fixed element ids or assume it's the only one; its own settings go in `ctx.windowState` / `ctx.saveWindowState(patch)` (saved with the layout). Each `render(body, ctx)` gets `ctx.signal` (aborted when the window closes): register bus listeners with `on(name, fn, ctx.signal)` (`js/bus.js`) and stop timers on it. After changing data, `emit("wallets-changed" | "transfers-changed" | "prices-changed")` so other windows refresh. Use `fill(el, ...)` (never `replaceChildren`, which prints "null"); format money with `js/format.js` (strings only, never `Number()` on amounts).
- **Writes lock first:** `get_db` starts write requests with `BEGIN IMMEDIATE`; anything else that writes (background jobs) must do the same (`IMMEDIATE` option), or parallel writes fail with "database is locked".
- **UI changes need browser proof:** run `pytest tests/ui` (real Chromium) and look at the screenshots in `tests/ui/screens/`.
- **Network access:** `BOT_HOST` may list several addresses; `BOT_ALLOWED_NETWORKS` is checked first in `app/main.py`. The main server never binds `0.0.0.0`.
- **Runtime settings that admins change** (like price history) live in the `app_settings` table as validated pydantic models, not in env vars.
- **CLI root handling:** a command that needs root re-runs itself through sudo (`app/cli/elevate.py`: `ALWAYS_ROOT`, `ROOT_WHEN_INSTALLED`, `NEVER`). Put every new command in one of those sets. `serve` must never be elevated. Tests block real `os.execv` (conftest).
- **CLI:** everything is a subcommand of `crypto-helper` (package `app/cli/`, one module per noun), noun first: `crypto-helper account <name> password`. Never accept a password or secret as a command argument (shell history, `ps`); prompt with `getpass` or read `--stdin`. CLI audit entries use the actor `<cli>`.
- **Service tooling** (`app/cli/service.py`, `update.py`, `deploy.py`, `doctor.py`): every path comes from `app/cli/layout.py`. Install code only via `deploy.install_commit` (clean `git archive`, umask 022). Any change here must pass `sudo .venv/bin/python -m toolchain.servicetest --replace-existing` on a VM without real data; it's destructive.
- **Embeds** (`app/embeds/`): the embed server is a separate app (`create_embed_app`) that may only serve embed pages, their CSS and PNGs (GET/HEAD). Anything an embed shows must have its own switch in `app/embeds/options.py` `ITEMS`; anything revealing holdings is `sensitive` and defaults off. `check_usable` re-checks the owner on every request. Where it listens: `BOT_EMBED_HOST=main` (default) follows `BOT_HOST` under the main server's bind rules; always go through `settings.embed_hosts_value`, never `embed_host` raw. Tests that need both servers: `SpawnedServer(embed=True)`.
- **Apps** (`app/apps.py`): every window is an app (or core, like settings). A new endpoint used by a window gets `dependencies=[Depends(require_app("<app>", ...))]` naming every app that calls it, next to its `require_permission`; core/account-security endpoints get none. A new window is added to `APPS` and `js/panels.js` together (`test_every_window_is_an_app_or_core`). The desktop shows what `/api/auth/me` `apps` lists.
- **Features and services** (`app/features.py`, `app/routers/services.py`): install-wide switches apply to everyone (super too); enforce with `features.require(db, key)`. Anything that needs root goes through the **agent** (`app/agent/`): add an op to `protocol.Request`, implement it in `Ops`, keep it a fixed action (never pass a command or path from the request). Endpoints that call the agent must `db.commit()` first (don't hold the write lock while it works). Throwaway servers (`SpawnedServer`) drop `BOT_*` env and get their own agent socket: keep it that way.
- **Console and Terminal** (`app/routers/shell.py`, `app/agent/console.py`, `app/agent/terminal.py`): console commands are ids mapped to fixed argv, never text. `terminal.use` is in `SUPER_GRANTS_ONLY`. The WebSocket does its own checks (HTTP middleware doesn't run for it): allowed networks, Origin, one-time ticket tied to the session, periodic re-check. xterm.js is vendored in `app/web/vendor/xterm/` (see its README); keep the canvas renderer loaded before `open()` so no `<style>` is injected under the CSP.
- **Tests run as root on this VM: never pass a real system path (`/etc/...`, `/run/crypto-helper-agent/...`, the live config) to code that writes or deletes, even as a "should be refused" example.** Use stand-ins in `tmp_path`. A mutation run that switched off a path check once deleted the VM's real `/etc/passwd` this way. Root-run code that creates files must never replace or delete anything it didn't make (link, not rename; check the inode before unlinking).
- **Tests run in parallel** (the check runner starts one pytest per file on every core): a test must never share anything with another file's tests: its own `tmp_path`/`mkdtemp` folders, port 0 for servers, no fixed file names outside them. Never depend on a 30-second 2FA window staying the same between two requests (reuse the exact code string instead).
- **Uploads of media** (wallpapers, theme bundles): never store or serve what was uploaded; re-encode it (`app/wallpapers.py`, `themes.clean_icon`). ffmpeg always gets `-f <format>` and `-protocol_whitelist file`. Zips go through `app/theme_bundle.read` (names, links, sizes, ratios) before anything is used, and nothing is written to disk under a name taken from inside a zip except by `unpack` into its own folder. Long conversions run without holding the database write lock (`_who` + manual session).
- **Display scale** uses CSS zoom: any code turning pointer positions or `getBoundingClientRect()` into style values goes through `screenToCss()` (`js/scale.js`); popup menus use `placeBelow()`.
- **Notifications** (`app/notifications.py`): create them only with `notify(db, hub, users, ...)` inside the caller's transaction (they're pushed live after commit). Pass `request.app.state.hub` (or the job's hub) so they pop up; `None` only from the CLI. Security events go through `app/alerts.py`, system health through `app/health.py` (transitions only, state in `app_settings`). Never put a secret in a notification. Holdings (amounts, values, wallet names, the portfolio's split) only inside `notifications.detail()` markers, so Discord gets them only if the person allowed that detail. Discord webhook addresses are secrets (encrypted, masked).
- **Prices and locks:** background jobs use `prices.fresh(session_factory)`; reading requests use `prices.snapshot(db)` (it ends the read transaction before fetching); requests that write must never fetch (`prices.last_snapshot`), and anything else that waits on the network (CoinGecko, the agent) commits first. The fetch can take 10 s and `busy_timeout` is 5 s.
- **Route rules** (`tests/test_route_audit.py`): every route needs a session unless it's in `PUBLIC`; every change writes an audit entry unless it's in `NOT_AUDITED` with a reason; API bodies are capped at 2 MB (uploads stream with their own limits). Secrets never go in URLs except embed tokens and terminal tickets, which `app/logredact.py` hides from the access log (`tests/test_log_secrets.py`).
- **Help window** (`app/help.py`, `js/panels/help.js`): shows `WIKI/` from the install. A new wiki folder needs a line in `pyproject.toml` `[tool.setuptools.data-files]` (`test_every_wiki_page_is_installed`); `test_every_wiki_link_resolves` checks links and `#anchors` (kramdown ids: leading digits dropped). New windows get a `guide:` in `js/panels.js`. Bus listeners get an event: read `e.detail`.
- **Dependencies are pinned** (`requirements.txt`: runtime, all transitive; `requirements-dev.txt`: plus test tools). A new dependency goes in `pyproject.toml` and pinned in the right file; upgrades follow `WIKI/reference/dependencies.md`. Installs/updates use `requirements.txt` as constraints. CI (`.github/workflows/tests.yml`) runs lint, unit tests, node tests and the tester on every push.
- **Syncing** (`app/sync/`, phase 2): exchanges register an `Exchange` (fields, `check`, `fetch`, asset `aliases`) in `EXCHANGES`; a client contains only reading calls (never order/withdraw endpoints). Keys are checked on save and before every sync (`check().read_only is False` → refused). The engine reads with no session open and applies under the lock; synced wallets' balances change only through it (`svc.require_manual` guards hand edits and practice transfers). Tests use the Demo exchange (`BOT_SYNC_DEMO=true` in conftest and the UI server). Real exchanges (`coinbase.py`, `kraken.py`, `gemini.py`, `binanceus.py`) go through `app/sync/http.py` only, list their paths in `READ_ENDPOINTS` (`tests/test_exchanges.py` enforces read-only paths), and are tested against a local fake that verifies signatures; check an exchange's current docs before changing its client. Trade history: `Exchange.trades(creds, state, assets)` returns `TradeRow`s and the state to resume from; the engine imports on Sync now and hourly (`TRADES_EVERY`), stores each trade once per wallet (`store_trades`), and a trade error never fails the balance sync. CSV formats live in `app/tax_csv.py` (headers from each tool's official template; `text()` guards spreadsheet formulas). On-chain (`app/sync/chains.py`): watch-only (refuse any extended private key); token contracts only from `networks.TOKENS` (verify a new one on-chain and with the issuer, and add it to `WIKI/reference/networks.md`, which a test checks); tests use the local `Chain` fake in `tests/test_chains.py`, never the public servers.
- **Balance history** (`app/balance_history.py`, 11e): `BalanceHistoryJob` (runs with the price job) snapshots every wallet when due (`interval_minutes`, or `MIN_GAP` after the holdings `signature` changes), fetching prices with no session open; never with stale or practice prices. Values are stored per fiat at record time (`BalancePoint.values`), so reading never fetches prices. `compact` keeps each day's last snapshot after `detail_days`. Points go with their wallet; the portfolio series covers today's wallets. Change maths (first→last) is done on the server (`change`), the UI only formats it (`format.js` `moneyChange`).
- **Account rules and onboarding** (12a): `app.deps.current_user` refuses an account with a pending rule (`restriction()`: `must_change_password`, or 2FA required via `require_2fa` / super + `BOT_SUPER_REQUIRES_TWO_FACTOR`) with `403 {restricted}`; only routes that use `current_session` (sign-out, password, 2FA, sessions, `/api/auth/me`, `/api/onboarding`) stay open, and `tests/test_account_rules.py` asks every route. Tests run with super's 2FA requirement off (conftest, `SpawnedServer`); turn it on in tests about it. The walkthrough is `js/onboarding.js` (reuses real screens; steps tick from data in `app/onboarding.py`, or are marked); the Getting started window is the core app `start`. The first sign-in of every account opens the walkthrough: UI tests sign in with `sign_in` (it closes it). Network changes from the browser: `app/netconfig.py` rules (checked by the web app and again by the agent), agent ops `network.set/confirm/state` keep `config.env.revert` and restore it unless the *restarted* web UI confirms (boot id); never `0.0.0.0`.
- **Alerts** (12a): `app/smart_alerts.py` (kinds `portfolio`, `wallet`, `drift`, `trend`; params validated by pydantic models; `SmartAlertJob` with the price jobs; wallet changes from `sync/engine.py` via `wallet_changed`, never on a wallet's first sync, never fetching prices under the lock). Daily prices: `app/prices/daily.py` (`DailyPriceJob`, Coinbase public candles, `BOT_DAILY_PRICES_URL`; tests use the local fake in `tests/test_daily_prices.py`). Anything that reveals holdings in a notification goes through `notifications.detail(kind, text, instead)`: the app renders it in full, Discord only with the person's `discord_details`; typed messages can't make markers.
- **Past prices** (12b): `app/prices/importer.py` (`PriceImport`, a thread, one at a time, status in memory + last result in `app_settings`). Imported hourly candles are `PriceCandle(source="coinbase")`, imported daily ones `DailyCandle(quote=fiat)`; they only fill time *before* the first recorded price, compaction replaces an imported candle with a recorded one, pruning only touches recorded ones. `history.query` joins daily → hourly → recorded without overlap and thins past `MAX_QUERY_ROWS`.
- **Live windows** (12b, `app/live.py`): a plain ASGI middleware (`LiveUpdates` in `app/main.py`) publishes `changed {topics}` after every successful API write, using `ROUTES` (a new write route needs an entry; `tests/test_live.py` checks every one) and `TOPICS` (who may hear each); background jobs call `live.publish(hub, factory, topics, only=…)` after committing. `me` tells an account its access changed (the desktop closes windows it lost); `open-window` is the admin remote open. Windows listen for the matching bus events (`wallets-changed`, `balances-changed`, `alerts-changed`…); only topic names travel.
- **Backtester** (12c, `app/backtest.py`): pure simulation over `DailyCandle` rows (`load` → `simulate`): decide on day t's close, fill at t+1's open with slippage and fee, benchmark = same flows bought and held. Money stays Decimal; only displayed ratios (return, yearly rate via `xirr`, worst drop from a time-weighted index) are floats. Fee presets in `FEES` (dated; re-check before changing). Saved runs: `BacktestRun`, own only, audited save/delete.
- **Paper trading** (12d, `app/bots.py`, `routers/bots.py`, `cli/bot.py`): a `Bot` has its own paper account (JSON on the row; never wallets, never the trade log). Decisions call `backtest.decide` (the backtester's code, shared; change strategy logic there only) on each finished UTC day; `BotJob.tick` (every minute, with the price jobs) fills `BotOrder`s at live prices with `fees`/`slippage`, applies limits, runs `check_risk`, keeps hourly `BotPoint`s. Never fill on practice or stale prices. Copy JSON columns before changing them (`dict(bot.account)`), or the change isn't saved. The kill switch (`trip`/`rearm`, state in `app_settings` `kill_switch`) is checked before every fill; it must stay usable from the CLI without the web server, and re-arming never starts a bot. The plan form is shared: `js/plan-form.js` (Backtester and Paper trading).
- **Readiness** (12e, `app/readiness.py`): project rule 10 as code. Clean days come from a bot's `state` (`clean_since`, `last_tick_at` (only set by a check that had prices), `paused_by`, `clean_reset`); `bots.resume` keeps the run only after a drill. A drill is `trip(..., drill=True)` + `drill_checked` (the job must refuse) + re-arm (recorded in `app_settings` `kill_drills`). The limits self-check runs `_scenarios` on throwaway in-memory databases and is tied to `risk_code()` (a hash of `app/bots.py`): any change to the engine needs a new self-check, which is intended. A new risk rule gets a self-check scenario. Phase 4's switch to turn live trading on must require `report(...)["live_allowed"]` (ready on the real clock). The test clock (`BOT_READINESS_TEST_CLOCK`, a day = a minute) is for development and throwaway servers only: `readiness.test_clock()` refuses an install's database or the service account; never weaken that.
- **Uninstall** (`app/cli/service.py`): `uninstall_plan` is the one list both `--dry-run` and the real run use; systemd and `userdel` only on the real root; the link only if it points into the install; the account only if `system.USER_COMMENT` says the installer made it. Anything new that install creates must be added to the plan and to `tests/test_uninstall.py`.
- **Uploaded images** go to Pillow with `formats=[...]` (only the decoder for the declared type), never a bare `Image.open`.
- **Live trading** (phase 4, `app/trading.py`, `routers/trading.py`, `cli/live.py`; plan in `WIKI/project/milestone-13.md`): real money. Trading keys (`TradingKey`, encrypted, personal or shared `owner_id=None`) are checked with `Exchange.check_trading` (permission/read calls only, never an order) and refused by `trading.verdict` if they can withdraw or can't trade; unknown withdraw rights need the person's confirmation. Switches per exchange in `app_settings` `live_exchanges` (on: super with 2FA; off: services.manage or `live off`). Caps per person (`users.live_cap`/`live_cap_ceiling`, default `DEFAULT_CAP` 150, no code maximum by the owner's choice); raising needs `require_code` (fresh TOTP). Live permissions are in no preset. Any order placed later must check: the switch, the key's owner/`may_use`, the cap, and readiness `live_allowed`. Orders: `app/orders/` (13b), one `OrderClient` per exchange using the sync client's `signed_call`, only paths in its `TRADE_ENDPOINTS` (`tests/test_orders.py` bans withdraw/transfer/deposit/convert/cancel and resting order types); always immediate-or-cancel, `prepare()` for sizes/protection/minimums, our `client_id` on every order, `OrderError.unknown` → `lookup`, never resend (Coinbase's lookup is the idempotent re-create it documents). Check an exchange's current docs before changing a client. Live bots (13c, `app/live_bots.py`): `Bot.mode == "live"`; `BotJob.tick` decides as for paper, then `live_bots.run`: **claim** (locked: every gate via `why_not`, cap via `owner_put_in`/`flow_room`, orders → `sending` with `client_id`, committed before sending), **send** (no lock), **record** (locked: `record_result` from the exchange's `Fill`); `sending` orders older than `LOOKUP_AFTER` are looked up, never resent; reserved cash (`state.reserved`) stays reserved while an outcome is unknown; `_reconcile` hourly. Live bots are only their owner's and super's (`_sees`). Never call an exchange while holding the lock. First tiny order (13d): `trading.first_order_done(key)` gates live bots (`why_not`, bot creation); endpoints in `routers/trading.py`. `live_bots.send` outcomes: retry (nothing sent) / unknown (look up) / refused / none / fill; use `orders.transient(e)` so a network failure is never read as an answer.
- **Features by milestone** (`WIKI/project/features-by-milestone.md`, asked for by the owner): every finished milestone part adds its plain-words section there in the same commit that marks it **done** in the roadmap (`test_every_done_milestone_lists_its_features`).
- **Settings docs:** a new `BOT_*` setting goes in `.env.example` and `WIKI/reference/configuration.md` too (`tests/test_docs.py`).
- **End-to-end checks:** when you add an endpoint, add checks in `toolchain/tester/suites/` too (new suite: register it in `suites/__init__.py` and give it a switch in `config.toml`). In live mode the tester may only change throwaway `t_*` users.

## Commands
```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/pip install -e .   # setup
.venv/bin/uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000   # run (migrates on start)
.venv/bin/python -m toolchain.checks --ui                            # every check, test files in parallel on every core (-j N), progress bars and times (owner's preference: use it, report its summary)
.venv/bin/python -m toolchain.checks --mutations FILE.py             # mutation checks (MUTATIONS list), parallel, each in a throwaway copy of the repo
.venv/bin/python -m toolchain.watch                                  # full-screen live view of a running check (q quits); --once for a snapshot
.venv/bin/pytest                                                     # unit tests
.venv/bin/crypto-helper test                                         # end-to-end tester (toolchain/tester/config.toml)
.venv/bin/ruff check . && .venv/bin/ruff format .                    # lint / format
.venv/bin/crypto-helper --help                                       # admin CLI
node --test tests/js/*.test.mjs                                                # window-layout maths
.venv/bin/pytest tests/ui                                            # browser tests (needs: pip install playwright && playwright install --with-deps chromium)
sudo ./install.sh                                                    # install as a systemd service
sudo crypto-helper doctor                                            # check an install
crypto-helper embed enable|disable|status                            # the embed server (asks for sudo)
sudo .venv/bin/python -m toolchain.servicetest --replace-existing    # DESTRUCTIVE full service lifecycle test
.venv/bin/alembic revision --autogenerate --rev-id 0003 -m "..."     # new migration after a model change
```
Tests use an in-memory SQLite DB via `create_app(Settings(database_url="sqlite://"))`; `tests/conftest.py` points `BOT_SECRET_KEY`, `BOT_STATE_DIR` and `CRYPTO_HELPER_ROOT` at throwaway values so tests never touch real keys or a real install (otherwise, as root on a machine with the service installed, CLI tests would switch the pytest process to the service user).
